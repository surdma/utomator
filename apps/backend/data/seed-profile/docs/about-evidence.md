# About page: evidence and attribution (October 2026)

This is an editorial evidence ledger for the \`/about\` page. The page distinguishes capabilities
(what work someone can do), technical vocabulary (tools/frameworks) and work evidence (how that
experience is demonstrated). It deliberately contains no invented skill percentages, users served,
revenue numbers, or GitHub contribution counts.

- **AEKO**, public \`MilliHub-dev/aeko-chain\`: \`apps/explorer/backend/Cargo.toml\` confirms Rust,
  Axum, SQLx and PostgreSQL in Explorer services; the public Explorer frontend package confirms
  React/Vite. Existing portfolio evidence notes the user's network/runtime and SocialFi work, but

- **Path Planning Algorithms**, public \`surdma/Path-Planning-Algorithms\`: README documents Python

## Attribution boundaries

Employment periods and educational credentials come from the existing portfolio and resume data.
Repository manifests support stack membership, not personal authorship of every dependency or every
file in a team repository.

Private-project evidence always links to an internal case study rather than exposing inaccessible
source URLs. Relvor is described as an early-stage venture. Future edits should extend this ledger
before adding new technology badges, attributing a broader engineering outcome, or claiming
user/customer adoption.

Technology SVG marks in \`public/images/tech/\` are from the Devicon open-source icon collection
(https://github.com/devicons/devicon, MIT license). They identify technologies and do not imply
endorsement.

## October 2026 information architecture update

The About page now focuses on biography, photo, roles, skills and employment. Project evidence and
open-source examples are located under /projects. Path-Planning Algorithms is a public Python
implementation catalog with Dijkstra, A*, RRT and RRT*; no commercial robot deployment is claimed.
MilliHub is presented as a current role without an inferred joining date. Employment history should
be confirmed by the portfolio owner rather than deduced from repository timestamps.

## Résumé and About taxonomy

Professional skills are capabilities such as system design, technical leadership and reliability
engineering. Technologies are grouped separately by language, backend, frontend, data, APIs, cloud,
deployment and testing. The résumé and About page share these technology categories to avoid drift.
AWS, Hetzner, Scaleway, Firebase, Supabase, Coolify and Dokploy were supplied by the portfolio owner
as experience claims; they are not independent proof of deployment to any specific provider.

## Technology classification revision

The shared taxonomy distinguishes backend frameworks, frontend/UI tooling, data/ORMs, API protocols
(including Server-Sent Events), background task queues, cloud providers, infrastructure deployment,
version control/CI and automated testing. Node.js, Express and OpenCV are not in the displayed
stack. Technology experience lists are portfolio-owner claims; they should not be interpreted as
proof of commercial deployment or authorship of every team dependency. The résumé displays the same
taxonomy in its sidebar, while professional capabilities remain separate from named technologies.
